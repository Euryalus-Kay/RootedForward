ROOT CAUSE (drives the 3 worst P1/P2 items): the stat-card renderer treats the numeric part of every "value" string as an integer, applies thousands-separator formatting, AND runs a count-up animation toward it. That is correct for true counts (~4,000, $250 million) but corrupts values that merely CONTAIN a number that is not a quantity: a year ("1955"), a year inside a phrase ("completed 1961"), and an ordinal street ("61st Street"). Fix in the graphic/stat-card function: add a per-stat flag like literal:true (or detect when the numeric token is a 4-digit year or is glued to letters such as "st"/"completed") so those values are typed out as a static string with NO comma-grouping and NO count-up. This single fix clears P1-1, P1-2, and P2-1.
